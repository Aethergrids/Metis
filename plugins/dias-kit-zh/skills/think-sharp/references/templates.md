# 模板

目录：项目研究概况 · 问题刻画（自顶向下） · 自底向上扩展计划 · 步骤记录 ·
工作量核算与界 · 代表性样本核对 · 报告表 · 实验提案 · 翻倍阶梯 ·
问题 × 系统矩阵。

## 项目研究概况

每个项目写一次，写在项目存放其文档的地方（AGENTS.md、CLAUDE.md 或一份研究 README），并保持它是最新的。目标、研究问题、实验定义和运行规则由用户决定；用户尚未确认的每一条都标为草稿。

```markdown
# 研究概况：<project>

## 目标（我们要改进的量）
- <名称>：<指标、单位、方向>，例如「降低尾延迟：每请求 p99，ms」
- ...

## 研究问题与论文章节
| 章节 | 研究问题 | 子问题 |
| --- | --- | --- |
| <主题，例如刻画> | <问题> | <...> |

## 实验定义（仅当用户决定时才改变）
- 负载：<操作、配比、参数>
- 数据：<来源、规模、生成器与种子>
- 输入与输出：<格式、汇>
- 硬件与限制：<机器、核数、内存、溢写、时限>

## 受测系统
| 系统 | 版本（锁定） | 基线配置 | 变体 |
| --- | --- | --- | --- |

## 噪声标尺
<每个设置的重复次数；测得的散布，同一批次之内以及跨实验系列>

## 运行规则（它们使迭代保持快；打破一条之前先问用户）
<每次运行的时限、线程数、重复次数、阶梯规程>
```

## 问题刻画（自顶向下）

每个本质问题一份；它是自底向上计划的输入。

```markdown
# 问题：<描述性名称，针对该负载类陈述>

类型：<功能（失败 / 错误 / 内存耗尽 / 无法表达） | 性能（时间 / 内存 / 成本）>
症状（实测）：<数字、单位、设置、来源>

## 边界与条件
| 变量 | 问题出现 | 问题不出现 | 阈值 |
| --- | --- | --- | --- |
| <数据规模> | <≥ 2^21 个键> | <≤ 2^20 个键> | <介于两者之间；原因> |

## 单变量扫描与瓶颈
| 被扫描的变量（其余固定） | 范围 | 各工况的瓶颈（资源或阶段，份额） | 转变于 | 转变揭示了什么 |
| --- | --- | --- | --- | --- |

## 本质（因果链，每一环都有标注）
<负载或数据的性质>（计数） → <系统中的机制>（推断 / 实测）
→ <消耗的资源>（实测） → <症状>（实测）
缺失的一环，若有，以及能补上它的测量：<...>

## 设计约束
- 任何解法必须：<...>
- 任何解法必须避免：<...>
- 它必须工作于其中的工况：<...>
```

## 自底向上扩展计划

根据刻画写一次；当某一步改变了已知内容时修订。每一行是一步或若干步；每一行只改变一个维度。

```markdown
| 顺序 | 设置 | 扩展的维度 | 它引入的新问题 | 它增加的主张 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 1 | 单线程、样本、离线、单节点 | （基础） | 本质问题本身 | 机制 | |
| 2 | 多线程 | 线程 | 争用、内存带宽 | 在核数上可扩展 | |
| 3 | 全量数据 | 数据规模 | 溢写、倾斜 | 在数据规模上可扩展 | |
| ... | | | | | |
```

## 工作量核算与界

在运行之前对实际输入计数，并对照一个已记录的值核对一次，以此作为门槛。硬件那几行把必需工作量变成一个界（第一性原理，SKILL.md 的第 1 节）。

```markdown
| 符号 | 含义 | 计数 | 如何计数 |
| --- | --- | ---: | --- |
| N | <读入的输入单位> | | <查询 / CLI> |
| D | <互异键> | | |
| P | <输出元素> | | |
| w | <每个输出元素的字节数> | | |
| s_max | <最大分区占工作量的份额> | | |

| 导出量 | 公式 | 值 |
| --- | --- | ---: |
| 任何正确计划必须做的工作量 | <...> | |
| <设计 A> / <设计 B> 所做的工作量 | <...> | |
| 冗余因子 | <所做工作量 / 必需工作量> | |
| 状态下界 | <例如，阻塞聚合的 P × w> | |
| 并行度界 | 1 / s_max | |
| 首先耗尽的资源，以及在何种规模 | <计数对照各项限制> | |

| 资源 | 容量（实测或规格） | 在其上的必需工作量 | 界 = 工作量 / 容量 |
| --- | --- | ---: | ---: |
| 内存带宽 | <GB/s> | <移动的字节> | <s> |
| 存储 / 网络 | <GB/s> | <字节> | <s> |
| 计算 | <ops/s> | <ops> | <s> |
| 内存容量 | <GiB> | <状态下界> | 放得下 / 放不下 |

时间上的界：<各界中的最大者>。实测：<s>。差距：<×>，拆成
冗余工作量 <份额>、做得慢的必需工作量 <份额>、等待 <份额>。
```

## 翻倍阶梯

```markdown
来源：<数据集>；维度：<被翻倍的量>；阶 k = ceil(N / 2^k) <单位>，按 <规则> 切片。
假设所需要的性质，在每一阶上计数：<例如每实体事件数>。
限制：<内存、溢写、时限>；重复次数：<n>。
运行配置：<固定的参数>。

| 阶 k | 单位 | 性质计数 | 工作量（由计数得出） | 实测（中位数，n） | 状态 |
| --- | ---: | ---: | --- | --- | --- |
| 17 | ... | ... | ... | ... | 正常 |
| ... | | | | | |
| 14 | ... | ... | ... | ... | 墙：溢写上限 / OOM / 超时 |
```

墙是第一个失败的阶。把可扩展性主张写成「当 <维度> 在 <范围> 上增长时，<设计> 在 <固定硬件> 上把 <指标> 保持在 <每单位成本>；它在 <阶> 失败，此时 <资源> 耗尽」。

## 问题 × 系统矩阵

```markdown
| 本质问题 | 机制 | <System A> | <System B> | <System C> |
| --- | --- | --- | --- | --- |
| <名称> | <为什么每个系统都付出它> | 已观察：<症状> | 潜在 | 由 <设计> 避开 |
```

把每个格子标为 **已观察**（附症状）、**潜在**（该设计会在更大规模上付出它），或 **已避开**（附该设计特征）。
