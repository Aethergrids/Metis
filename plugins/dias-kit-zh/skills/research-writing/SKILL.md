# 研究写作

研究文本属于科学写作。诗歌的写法在这里不成立。检验标准：一位怀有敌意、同时很谨慎的读者（逻辑学家、审稿人）读这个句子，能够从中推出恰好一个含义，并且能够核验这个含义。作者头脑中的想法不算数；只有写下的文本算数。少用词，多举例子。

以下规则对每一种语言都成立。例如在中文里，显著、大幅、明显、远超都需要数字和依据，正如 "significant" 和 "much faster" 需要数字和依据一样。

## 1. 规则

| 规则 | 不要写成 | 写成 |
| --- | --- | --- |
| **写精确。** 点名组件、数据集、大小和度量。 | 「在更大的数据上，连接很慢。」 | 「规模因子为 100 时，哈希连接的构建阶段占算子时间之和的 58%。」 |
| **量化。** 每个比较词都需要数字和单位。 | 「快得多，内存也更低。」 | 「延迟降低 1.24×（212.4 → 171.3 s，3 次的中位数）；峰值内存 41.2 → 38.9 GiB。」 |
| **使用主动语态。** 点名施动者，使读者知道是谁做的、谁为这条论断负责。 | 「数据被过滤，并且观察到加速。」 | 「该重写在连接之前过滤行；延迟下降 19%。」 |
| **禁止拟人。** 系统、优化器、算子和计划不会想要、思考、尝试、知道、决定、偏好、看见、挣扎或受苦。描述组件做了什么，并写明机制。 | 「优化器想要先排序。」 / 「引擎不知道输入已经有序。」 / 「窗口算子在倾斜下挣扎。」 | 「优化器把排序放在连接下方。」 / 「对该输入，计划不携带有序性属性，因此引擎再次排序。」 / 「键倾斜时，一个分区持有窗口行数的 40%。」 |
| **禁止夸张。** 最高级和强化词是没有证据的论断。 | 「一项戏剧性的、巨大的改进，解决了内存墙。」 | 「峰值内存下降 6%；能够完成的最大输入从 2^20 个键增长到 2^21 个键。」 |
| **保持一致。** 一个概念只用一个术语，定义一次，在正文、表格、图和代码中处处沿用。同一事物再用第二个词，读起来就是另一个事物。 | 一段里写「查找点」，下一段写「探测」，表里写「查询点」。 | 全文使用「查找点」，并在首次使用时定义。 |
| **客观论证。** 每一个「因此」都必须从已陈述的证据推出；推不出时，写明「我们推断」或「假设」。 | 「所以瓶颈显然是归并阶段。」 | 「改动之后，归并阶段占算子时间的 39%（推断：优化后的那次运行没有做性能剖析）。」 |
| **在出现处定义符号。** 对话和幻灯片里每次都定义；论文或记录里在首次使用时定义，并列入符号表。 | 「P 比 D 增长得更快。」 | 「P（输出位置）比 D（不同键）增长快 4×。」 |
| **写明论断的边界。** 一项结果在产生它的那套设置上成立。 | 「该重写消除了内存问题。」 | 「在单节点、64 GiB 上限下，该重写最多完成 2^22 个键；更大的输入没有运行。」 |
| **点明所在区间。** 瓶颈属于某个变量的一段取值范围。 | 「系统受内存带宽约束。」 | 「从 8 个线程起，扫描受内存带宽约束（41 GB/s 中用到 38）；低于 8 个线程时，扫描受计算约束。」 |
| **对类下论断，引用实例。** 论文的论断必须对一类工作负载或系统成立；本项目的表和数据集是该类的例子。 | 「我们的规则加快了价格查找。」 | 「对版本化表的查找，该规则去掉每次请求的排序（在我们的工作负载中，即价格历史表：延迟降低 1.4×）。」 |

## 2. 文本中的数字

- 把数字放进它所支持的论断的同一句里。主题句带一个形容词，证据在两句之后才出现，读起来就是一条没有依据的论断。
- 数字若是估计、推断或单次运行，要在同一句里说明。"About"（大约）、"roughly"（大致）和 "significant"（显著）各自都需要依据（significant：运行次数，以及相对噪声的散布）。
- 同时给出绝对差和相对差（「212.4 → 171.3 s，1.24×」）。
- 数字与单位写在一起。每个「每 X」句子都先核对单位：单位成本按总量除以单位数得到，不取总量的斜率。
- 写明计数器量的是什么：「算子时间之和的份额」不能当作墙钟时间，也不能当作操作系统 CPU。
- 报告新数字；旧数字只作为上下文出现，并且标明为上下文。

## 3. 名称与标签

- **变体按其本身命名：** 原装默认配置写成 `<System> Vanilla`，其后写成 `<System> + <optimization>`。一次构建不等于一个版本。
- **禁止实验代号或问题代号。** 读者会看到的任何地方都不得出现 J1、S2、RQ3、H1、E8。J1 与 S2 是字母加数字的实验编号，RQ3 是研究问题 3 的编号，H1 是假设 1 的编号，E8 是实验 8 的编号。直接称呼事物本身（「填充版本实验」、「阶段分解」）。若对某个文件的交叉引用必须使用代号，把代号放在描述之后的括号里，并且只放一次。发送前，在文本中搜索 `\b[A-Z]\d\b` 和 `RQ\d`。
- **禁止内部行话。** 代理、面板或脚本自造的标签对读者没有意义：arm（把一组条件叫作一支臂）、gate（把一项检查叫作一道门）、lane（把一条并行路线叫作一道）、track B（把一条路线叫作 B 轨）。按版本改了什么来描述该版本（「在连接之前过滤版本，而不是在连接之后」），按检查核验什么来描述该检查（「输出校验和相等」）。

## 4. 对话回复与记录

两处场合，两种长度。读者会把数字贴进幻灯片和决策里，也可能在手机上读这段对话。

- **记录**（步骤笔记、实验系列的 campaign README、报告）是文件，容纳全部内容：设置、数字、推导、限制条件。
- **对话回复**是那项决策或一张表，再加最多五行短句：改了什么、这意味着什么、接下来做什么。链接记录，不要把记录再写一遍。回复若需要第二屏，就是太长；先删解释，再删数字。
- **短不等于晦涩。** 对每一项都要说明它是什么、它改动哪个组件、该组件在流水线的什么位置、它回答哪个问题、实验如何设计、结果是什么、要点是什么。错过最近三次会话的读者应当能够看懂。

## 5. 交付可直接发出的文本

事实不确定时，写出最可辩护的版本，并把不确定之处标在文本之后；文本内部不留空白、占位符或 TODO。收紧别人的文本时，保留其中的论断和数字；只有为了让论断与其证据相符才改论断，并说明改了哪些论断。

## 6. 发送之前

以逻辑学家的身份把文本重读一遍：

- 每个比较词都有数字、单位和依据；
- 每个施动者都已点名，并且没有任何地方把机器拟人化；
- 每个符号都在出现处得到定义；
- 一个概念只用一个术语；
- 没有代号，没有内部行话；
- 每条论断都写明边界，每一个「因此」都从已陈述的证据推出；
- 对话回复放得进一屏，并链接记录。
